# نديم | Nadeem

منصة نديم لحجز المرشدين السياحيين في السعودية، بواجهة عربية RTL وإنجليزية LTR. اكتمل التأسيس، وأضيف تنفيذ الحسابات وملفات المرشدين والمراجعة الإدارية. **طُبقت مهاجرات الحسابات على Supabase وفُحصت صلاحياتها؛ نُشرت النسخة التجريبية وضُبطت روابط Auth؛ أكد المالك نجاح التسجيل والدخول؛ اختبار الاستعادة والخروج وتسليم البريد ما زال مطلوبًا. الحجز والدفع غير منفذين.**

النسخة المنشورة: [نديم](https://nadeem-rkq4.onrender.com/ar). إعداد الخدمة والفحوص موثقة في [دليل Render](docs/RENDER_DEPLOYMENT.md).

## التشغيل المحلي

المتطلبات: Node.js 22 أو أحدث، وnpm. الملف `.nvmrc` يختار Node.js 24؛ جرى التطوير عليه.

```bash
npm ci
npm run dev
```

افتح [العربية](http://localhost:3000/ar) أو [الإنجليزية](http://localhost:3000/en). المسار `/` يحوّل إلى العربية. الخادم مربوط بالواجهة المحلية `127.0.0.1`.

الواجهة العامة تعمل دون Supabase. لتشغيل الحسابات انسخ `.env.example` إلى `.env.local` واملأ الرابط والمفتاح العام و`NEXT_PUBLIC_SITE_URL`. ملف البيئة المحلي مستبعد من Git. يلزم تطبيق المهاجرات وإعداد روابط Auth أيضًا؛ وجود المفتاح وحده لا يجهز قاعدة البيانات. اتبع [دليل ربط الحسابات](docs/ACCOUNTS_SETUP.md). استخدم `localhost` باستمرار مع الإعداد الحالي، لأن رابط التأكيد يعتمد على cookie في المتصفح نفسه.

للتحقق من نسخة البناء:

```bash
npm run build
npm run start
```

## الفحوص

```bash
npm run check
# lint + TypeScript + unit/database/asset tests + production build
npx playwright install chromium
npm run test:e2e
```

شغّل الاختبارات الشاملة بعد البناء، وأوقف أي خادم يستخدم المنفذ 3000؛ Playwright يبدأ خادم الإنتاج وينهيه بنفسه. إذا كان Chromium متوفرًا مسبقًا يمكن تحديده، دون تغيير إعدادات المشروع:

```bash
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/absolute/path/to/chrome npm run test:e2e
```

اختبارات قاعدة البيانات تستخدم **PGlite، محرك PostgreSQL محليًا داخل عملية الاختبار**، لتطبيق ملفات المهاجرات فعليًا وفحص القيود ومنع الوصول وRLS. تنشئ دورَي `anon` و`authenticated` داخل قاعدة مؤقتة فقط. تحاكي جدول `auth.users` وهوية المستخدم لاختبار فصل الحسابات والصلاحيات وانتقالات المراجعة. لا تختبر إرسال البريد أو JWT أو تجديد جلسة Supabase الحقيقية، ولا وظائف الحجز غير المنفذة.

## قاعدة البيانات المحلية

`supabase/config.toml` إعداد محلي، ومجلد `supabase/migrations` يحتوي مهاجرات السياسات والحسابات وعزل دوال المراجعة. لتشغيل حزمة Supabase محليًا تحتاج Docker وSupabase CLI. الإعداد المحلي منفصل عن المشروع السحابي؛ تعديل TOML لا يغيّر إعدادات ذلك المشروع.

```bash
npx --yes supabase@2.118.0 start
npx --yes supabase@2.118.0 migration up --local
npx --yes supabase@2.118.0 status
# بعد الانتهاء
npx --yes supabase@2.118.0 stop
```

`start` يطبق المهاجرات على قاعدة جديدة، و`migration up --local` يطبق المهاجرات اللاحقة على البيئة المحلية. لا يلزم حذف قاعدة محلية لإكمال الإعداد. للبيئة السحابية اتبع دليل الربط بعد التحقق من المشروع ومراجعة خطة المهاجرات. لا تنسخ مفاتيح الخدمة إلى المتصفح.

Auth والبريد التجريبي المحلي مفعّلان في TOML. Storage وRealtime والتحليلات معطلة. إعدادات المنصة ممنوعة عن العميل، وجداول الحسابات محمية بسياسات RLS وعمليات كتابة محددة عبر RPC. لا يُمنح دور المسؤول من نموذج التسجيل.

## بنية المشروع

```text
src/app/                 الواجهة وحالات التحميل والخطأ و404
src/components/          الهوية والتنقل والتذييل
src/content/messages.ts  نصوص العربية والإنجليزية
src/lib/                 اللغة والتنسيق وحدود القدرات
src/proxy.ts             اشتقاق اللغة وتجديد جلسة الحساب
public/                  نسخ مطابقة للشعار والأيقونات
supabase/                إعداد محلي ومهاجرات قابلة للتتبع
tests/unit/              تنسيق، أصول، مهاجرات، صلاحيات وفصل الحسابات
tests/e2e/               فحوص المتصفح للجوال والكمبيوتر
docs/                    الخطة والقرارات وتقرير الفحوص
nadeem-brand-kit/        حزمة الهوية الأصلية، دون تغيير
```
