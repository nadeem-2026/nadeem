اختبارات SQL تطبق المهاجرتين على PGlite. تشمل رفض طلب دور admin من metadata، ومنع تغيير الدور بتعديل metadata، وفصل ملفات المستخدمين، ورفض الكتابة المباشرة والاعتماد الذاتي، ومنع الحساب غير المؤكد أو الموقوف، وحالات إرسال الملف ورفضه وإعادة إرساله واعتماده وتعليقه وإعادة اعتماده، وسبب القرار وسجل التدقيق، واستمرار RLS حتى مع إضافة grants عرضية داخل الاختبار.

اختبارات المتصفح تشمل نماذج التسجيل بدورَي سائح ومرشد فقط، حدود كلمة المرور، حماية صفحات الحساب والمراجعة وتحديث كلمة المرور للزائر، حفظ المسار عند تبديل اللغة، ورفض إعادة التوجيه الخارجي في callback، إضافة إلى فحوص واجهة التأسيس والتجاوب و404. لا تُرسل هذه الاختبارات نموذج تسجيل حقيقيًا.

ملاحظة البيئة: اتصال npm بطيء وتطلب تحديث بيانات الذاكرة المؤقتة؛ اكتمل التثبيت في 15 دقيقة. محاولة TypeScript قبل اكتمال تنزيل ملفات Next أظهرت تعريفات ناقصة؛ نجح الفحص الكامل بعد انتهاء التثبيت دون تجاوز أخطاء النوع. تنبيه تقادم ESLint 9 موثق في سجل القرارات.

## التحقق السحابي وحدوده

- طلب قراءة مباشر إلى `/auth/v1/settings`: HTTP 200، التسجيل مفعّل، البريد مفعّل، والتأكيد مطلوب (`mailer_autoconfirm=false`).
- طلب قراءة مجهول بالمفتاح العام إلى `/rest/v1/profiles`: HTTP 404 مع `PGRST205` (الجدول غير موجود في schema cache). لم يُطبّق SQL على المشروع السحابي في هذه المتابعة؛ هذه ليست نتيجة نجاح لاختبار RLS السحابي.
- لم تُرسل رسائل تسجيل أو استعادة، ولم تُنشأ حسابات تطبيق حقيقية أو تُمنح صلاحية مسؤول.
- اختبارات PGlite تحاكي جدول مستخدمي Auth وهوية الجلسة، ولا تتحقق من JWT أو تجديد جلسات Supabase الحقيقية أو تسليم البريد.
- بعد تغيير اتصال GitHub، تأكد حساب `nadeem-2026` وبريده، ووجود مستودع `nadeem` الخاص وصلاحية الكتابة عبر الإضافة. مصادقة `gh` القديمة مستقلة عن هذا الاتصال.
