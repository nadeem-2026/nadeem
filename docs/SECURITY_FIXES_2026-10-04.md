## ما تغير

- منع INSERT/UPDATE/DELETE المباشر للحجوزات من مستخدمي Data API، واستبدال إنشاء الطلب والقبول والرفض والإلغاء بدوال تتحقق من الهوية والدور والحالة داخل قاعدة البيانات.
- حساب السعر وتثبيته داخل DB، والتحقق من اعتماد المرشد وحساب نشط والسعة والتوفر الأسبوعي والاستثناءات ومهلة 24 ساعة. واجهة الموعد ترسل offset الرياض صراحة.
- تسلسل قبول الطلبات بقفل صف المرشد، وفحص التداخل والفاصل المحفوظ (الافتراضي 30 دقيقة). إضافة مهلة رد ودفع؛ انتهاء مهلة الدفع يحرر الوقت عند فحص التعارض. لم تُضف بعد مهمة دورية تغير الحالات المنتهية وترسل إشعاراتها.
- وقف جميع معالجات الدفع الحالية. الـwebhook يعيد 503 دون كتابة، وصفحة العودة لا تدعي نجاح الدفع، وإنشاء Charge لا يتصل بالمزود. دالة الدفع القديمة مسحوبة من الأدوار وتفشل حتى عند استدعاء مالكها. إعادة التفعيل تحتاج تكاملًا موثقًا واختبارات الدفع والتكرار والاسترداد؛ لا يكفي وضع مفتاح بيئة.
- نقل أسرار بدء الجولة إلى جدول private محجوب، وإبقاء العمود المشترك NULL. الوصول للرمز يقتصر على السائح صاحب الجولة المؤكدة. الترحيل يدور الرموز القديمة إن وجدت؛ لا توجد في الإنتاج وقت الفحص. الرمز ينتهي عند نهاية الموعد الحالي، ويستهلك مرة واحدة، وبعد خمس محاولات خاطئة يُرفض. تحديد نافذة بدء الجولة وإعادة إصدار الرمز الآمنة ما زالا مطلوبين قبل التشغيل المالي.
- منع المستخدمين من إنشاء إشعارات للآخرين؛ السماح بتعديل is_read فقط. إضافة notifications إلى Realtime. إنشاء الطلب وتغيير حالته يكتبان إشعارهما داخل المعاملة نفسها.
- إصلاح إذن حفظ ملف المرشد والتحقق من سعر غير صالح/NaN. إعادة استخدام مسار الاعتماد ذي السبب وسجل التدقيق بدل is_verified غير الموجود. صفحة قائمة المراجعة تستخدم RLS وجلسة المسؤول، وتتحقق صفحات الإدارة من الدور عند القراءة.
- استبدال أعمدة البحث غير الموجودة بـRPC يعيد بيانات عامة محددة للمرشدين المعتمدين النشطين فقط؛ لا يكشف أسباب المراجعة أو بيانات الحساب الخاصة. توحيد مرادفات فلترة المدينة واللغة بين العربية والإنجليزية. أخطاء الاستعلام تظهر كخطأ تحميل بدل قائمة فارغة مضللة.
- إزالة الأسعار الثابتة والحقول الوهمية من الصفحة الرئيسية، وتصحيح inclusions، وحذف مدخل التاريخ وروابط الاهتمامات التي لم تكن تفلتر النتائج. بقي تصميم الصفحة والأصول الأصلية. استُبدلت صور Unsplash المعطلة مؤقتًا برمز الهوية المحلي؛ يلزم اختيار صور وجهات حقيقية لاحقًا.
- إزالة any من المكونات التي كانت تفشل lint، وإصلاح ترتيب دالة جلب الإشعارات وتنظيف الاشتراك عند مغادرة الصفحة. الأنواع كشفت أيضًا عدم تطابق حقل الخدمات في ملف المرشد وأُصلح.

## قاعدة البيانات المنشورة

طُبق الترحيل `20261004175135_secure_booking_and_guide_access.sql` على المشروع القائم. طابق اسم الملف رقم سجل الترحيلات الذي أعاده Supabase بعد التطبيق. قبل التطبيق: 0 حجوزات، 0 مدفوعات، 0 جولات مؤكدة/جارية، 0 رموز قديمة؛ لم تتغير حسابات المستخدمين أو ملفاتهم.

التحقق بعد التطبيق أكد:

- anon/authenticated لا يستطيعان تنفيذ handle_payment_webhook.
- authenticated لا يملك UPDATE على bookings ولا INSERT على notifications، ويملك UPDATE على is_read فقط.
- إذن private.save_guide_profile صحيح؛ دواله تتحقق من الهوية داخليًا.
- عدد الرموز في الصفوف المشتركة صفر؛ notifications منشور في Realtime.
- لا يوجد حاليًا مرشد معتمد نشط في نتيجة البحث العام؛ هذه نتيجة فعلية بعد إصلاح الاستعلام.
- اختفت تحذيرات SECURITY DEFINER العامة الحساسة. بقي تحذير [btree_gist في public](https://supabase.com/docs/guides/database/database-linter?lint=0014_extension_in_public) وتحذير [حماية كلمات المرور المسربة](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection). لم تتغير الخطة المجانية. تنبيها عدم وجود سياسات لـplatform_settings ولأسرار الجولة مقصودان لمنع وصول API المباشر.

## الاختبارات

- lint: نجح دون أخطاء أو تحذيرات.
- TypeScript: نجح.
- جميع ملفات اختبارات الوحدات السبعة نجحت. أُصلح helper بإضافة btree_gist وpublication وأدوار الاختبار، وقراءة الملفات المرقمة فقط دون schema_dump.sql، وتحديث استدعاءات دالة المرشد إلى توقيعها الحالي.
- اختبار booking-security يستخدم قاعدة PGlite معزولة وحسابات وهمية ويغطي الصلاحيات والسعر والتوفر والتداخل والفاصل والرمز ومحاولاته والدفع المغلق والإشعارات. لا يجري تحويلًا ماليًا ولا يكتب مستخدمين في الإنتاج. فحص قبول طلبين هنا ليس اختبار حمل متعدد الاتصالات؛ هذا مطلوب لاحقًا على Postgres مستقل.
- بناء الإنتاج نجح باستخدام `npm run build -- --webpack` خارج العزل؛ قيود العمليات الفرعية منعت البناء داخله.
- راجع نتيجة التحقق النهائية أدناه لحالة E2E والنشر.

## المتبقي قبل إطلاق تشغيلي

1. اختيار/اعتماد مزود Marketplace، الرسوم والضرائب، والتحصيل والاسترداد ومحاولاتهما والتسوية والصرف وتجميد المستحقات عند الاعتراض. الدفع مغلق حتى اكتمال ذلك.
2. إنهاء الطلبات آليًا وإشعارات المهل، معالجة الحجوزات القديمة إن وُجدت مستقبلًا، حدود المدة والجولات العابرة لمنتصف الليل، ونافذة البدء والجولات العالقة. الفحص الحالي يقبل توفرًا داخل اليوم الواحد.
3. استكمال سياسة الإلغاء، وتقييمات/شكاوى مرتبطة حتمًا بمرشد الحجز، وإخفاء التقييمات بتدقيق، والإبلاغ عن عدم الحضور، ووصول المسؤول لمحادثة الشكوى.
4. قناة موقع خاصة وصلاحياتها ودورة حياة المراقب وآخر تحديث؛ تظل ميزة الموقع ممنوعة بسياسة المتصفح الحالية. نافذة المحادثة 24 ساعة بعد الإكمال ومعالجة انقطاع الاتصال وأخطاء الرسائل.
5. البريد عبر outbox وإعادة المحاولة ومنع التكرار، وتغطية جميع الأحداث، وتوطين روابط الإشعارات. لم يُفترض تفعيل SMTP.
6. صفحات الشروط والخصوصية ووسيلة الدعم الفعلية، الصور النهائية، تعديل الملف بعد الاعتماد بسياسة مراجعة، وإدارة العمليات والإعدادات كاملة.
7. اختبار قبول حقيقي بأدوار منفصلة، البريد عبر متصفحين، دفع تجريبي لدى المزود، التزامن على Postgres، الاستعادة من النسخ الاحتياطية والمراقبة، وإعادة تقييم AC-01 إلى AC-24.

## إعادة التشغيل والفحص

استخدم Node المحدد في `.nvmrc` ثم `npm ci` و`npm run dev`. إعدادات الحسابات في `.env.example`. لم تُضف مفاتيح مالية أو خدمة جديدة. `npm run lint`، `npm run typecheck`، `npm test`؛ ثم البناء و`npm run test:e2e` (يشغل خادم اختبار على 127.0.0.1:3000).

سكربت `docs/audits/readiness-repro.mjs` يحتفظ بإعادة إنتاج الحالة التاريخية قبل الإصلاح، ويستبعد الترحيلات الأحدث عمدًا. اختبار السلوك المصحح هو `tests/unit/booking-security.test.ts`.

أضيف `/api/health` لفحص حياة خدمة الويب دون كشف إعدادات أو استدعاء مزود مالي. لا يعني نجاحه أن الدفع أو قاعدة البيانات مستعدان تشغيليًا.

## نتيجة التحقق قبل الرفع

اجتازت النسخة النهائية 36/36 اختبار Playwright للحاسوب والهاتف، بعد تصحيح محدد النص المكرر والانتظار لجاهزية DOM بدل انتظار جميع الموارد الخارجية. تشمل الفحوص تحميل الأصول المحلية واتجاه اللغتين والنماذج وإعادة التوجيه وحواجز الإدارة ومعالجة رابط الاستعادة الخالي من الرموز ومسارات الدفع المغلقة. لا تشمل تسجيل دخول فعليًا متعدد الأدوار أو دفعًا تجريبيًا لدى المزود.
